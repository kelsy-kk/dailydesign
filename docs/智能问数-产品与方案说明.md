## 1. 产品定位与建设现状

### 1.1 定位

**智能问数**是以自然语言驱动数据查询与分析的平台。核心思路：

**湖仓数据 → 数据治理 → 统一语义层 → LLM/NLP 问数引擎 → 多场景应用**

用户用自然语言提问，引擎结合元数据、指标、术语、SQL 问答对完成语义解析，生成 SQL 或图表，在统计分析门户、施工台账、问数助理等场景中返回答案；运营侧通过 LLM 管理、提示词与反馈持续优化。

### 1.2 建设状态

| 状态     | 含义                         |
|----------|------------------------------|
| 升级中   | 既有能力迭代                 |
| **建设中** | 当前阶段重点（架构图高亮） |
| 待研发   | 规划能力                     |

### 1.3 当前建设重点（架构图橙色项）

- 历史提问（输入侧 + 运营管理）
- 元数据提问、指标提问
- LLM 管理、SQL 问答对、术语管理、动态提示词
- 数据指标、数据标签

## 2. 分层架构要点

### 2.1 分层结构（自下而上）

| 层级       | 核心职责 |
|------------|----------|
| **湖仓底座** | 库表、文本、接口、采集等多源原始数据 |
| **数据治理** | 集成、开发、数据服务等，加工成可用资产 |
| **数据层**   | 统一元数据、数据血缘、数据指标、数据标签 |
| **功能层**   | 问数引擎（输入/提问类型）+ 运营管理 |
| **场景层**   | 统计分析门户、施工台账生成、应用问数助理 |

### 2.2 场景层（三大入口）

1. **统计分析门户** — 报表/分析类查询  
2. **施工台账生成** — 业务台账结构化输出  
3. **应用问数助理** — 对话式智能问数  

### 2.3 功能层

**输入能力：** 输入联想、历史提问、模糊匹配、数据集切换  

**提问类型：** 元数据提问、指标提问、NLP 追问、自然语言转图表（NL2Chart）  

**运营管理：** LLM 管理、SQL 问答对、术语管理、历史提问、动态提示词、显隐反馈  

### 2.4 数据层（语义基石）

- **统一元数据**：模型、数据集、维度、指标口径  
- **数据血缘**：追溯来源与加工链路  
- **数据指标 / 数据标签**：支撑指标问数与语义匹配  

### 2.5 核心逻辑链

```
湖仓底座 → 数据治理 → 统一元数据/指标/标签/血缘
         → LLM + NLP 问数引擎 ← 运营管理配置
         → 统计分析门户 / 施工台账 / 问数助理
```

### 3.1 特性说明摘要

**① 平台导航**  
通过数据中台、数据工具链、建模中心、应用中心进入智能问数，体现问数嵌入统一数据资产体系。

**② 会话历史**  
按会话保存历史问数，支持新建对话与回溯，支撑连续追问与专题复盘。

**③ 场景引导**  
对话式入口说明 AI-CHAT 价值，降低首次使用门槛。

**④ 元数据探查**  
自然语言查询模型、数据集、维度、指标及字段口径，回答「能问什么、是什么意思」。

**⑤ 分析问句**  
趋势、排名、对比、汇总等经营分析问题，由引擎解析为可执行查询。

**⑥ 问询范式**  
明示三类典型句式，提升语义识别准确率。

**⑦ NL 输入**  
核心入口：意图识别 → 语义映射 → SQL/图表 → 结果呈现。

**⑧ LLM 编排**  
可切换底层大模型，用于意图理解、澄清与回答生成。

**⑨ 推荐问题**  
运营/系统预置标准问法，缩短冷启动。

**⑩ 模型看板**  
浏览可问数语义资产，按看板/文档/表格等筛选。

**⑪ 模型数据集树**  
分层展示业务模型与数据集，是 NL2SQL 结构化知识来源。

**⑫ 维度/指标标注**  
字段级标注维度与指标，支撑 GROUP BY 与聚合规则选择。

### 4.1 元数据探查 vs 分析问句

| 类型 | 回答的问题 | 是否强调聚合 |
|------|------------|:------------:|
| 元数据探查 | 有什么、什么意思 | 否 |
| 分析问句 | 多少、趋势、排名、对比 | 是 |

### 4.2 NL2SQL 标准链路

```
自然语言输入 → 意图识别 → 语义解析（模型/数据集/维度/指标/筛选）
→ NL2SQL → 执行与可视化 → 反馈闭环（显隐反馈、SQL 问答对沉淀）
```

## 5. 提问分类场景与方案

### 5.1 总体分类框架

| 大类 | 目标 | 是否生成 SQL | 典型阶段 |
|------|------|:------------:|----------|
| **认知类（元数据问数）** | 弄清能问什么、字段含义 | 否 | 初次使用、建模后探查 |
| **分析类（指标问数）** | 得到多少、趋势、排名、对比 | 是 | 日常经营分析 |
| **交互辅助类** | 降门槛、消歧、纠错 | 视情况 | 全流程 |

```
用户提问 → 意图识别 ┬→ 认知类 → 元数据列表/定义说明
                    ├→ 分析类 → 语义解析 → SQL → 图表/表格/KPI
                    └→ 辅助类 → 引导/澄清/超范围
```

### 5.2 认知类（6 种场景）

| 场景 | 识别特征 | 示例问法 | 处理方案 | 输出形态 |
|------|----------|----------|----------|----------|
| 业务模型浏览 | 模型、有哪些模型 | 都有哪些模型？ | 读取业务模型目录 | 模型与数据集卡片 |
| 数据集浏览 | 数据集、数据表 | 有哪些数据集？ | 合并至模型浏览 | 同上 |
| 维度浏览 | 维度、可分析维度 | 都有哪些维度？ | 展开维度字段 | 维度列表 |
| 指标浏览 | 指标、业务指标 | 都有哪些指标？ | 展开 metrics | 指标列表 |
| 度量浏览 | 度量 | 都有哪些度量？ | 展开 measures | 度量列表 |
| 口径/定义查询 | 是什么、怎么算、口径 | 合同额是什么意思？ | 匹配字段定义 | 口径说明 |

**方案要点：** 依赖统一元数据与模型看板；不查明细事实表；为 NL2SQL 提供字段词典。

### 5.3 分析类（7 种场景）

| 场景 | 识别特征 | 示例问法 | 处理方案 | 输出形态 |
|------|----------|----------|----------|----------|
| 汇总统计 | 查、统计、按、各、每 | 按区域统计订单金额 | GROUP BY + SUM | 柱状图 + 表格 |
| 趋势分析 | 趋势、环比、各月 | 今年各月销售趋势 | 时间维度 + 折线 SQL | 折线图 + 表格 |
| 排名分析 | 排名、Top、最高 | 合同额最高的五省 | ORDER BY + LIMIT | 条形图 + 表格 |
| 占比分析 | 占比、比例、份额 | 各品类销售量占比 | 分组 + 占比计算 | 环形/饼图 + 表格 |
| 对比分析 | 对比、vs、相比 | 美式与拿铁销量对比 | 提取对比对象 | 对比表 |
| 核心指标 KPI | 总共、合计、一共 | 今年合同额一共多少 | 单值聚合 | KPI 数字卡 |
| 明细查询 | 明细、列出、清单 | 列出销售全部明细 | SELECT 明细 | 纯表格 |

**统一分析链路：**

```
提问 → 意图分类 → 数据集/字段匹配 → [多数据集则澄清]
     → 数据解释表（模型/数据集/维度/指标/筛选）
     → SQL 生成 + 语义推理叙述 → 执行查询 → 图表/表格/KPI
     → 反馈 + 相关问题推荐
```

**可视化策略：** 趋势→折线；排名→条形；占比→环形；对比→对比表；KPI→数字卡；明细→无图。

### 5.4 交互辅助类

| 场景 | 触发条件 | 处理方案 | 输出形态 |
|------|----------|----------|----------|
| 问候 | 你好、您好 | 能力说明 + 快捷入口 | 智能引导面板 |
| 使用帮助 | 怎么用、能做什么 | 列举问法类型 + 示例 | 引导面板 |
| 澄清选择 | 多数据集同分；仅有指标词 | 弹出数据集选项 | 确认选项面板 |
| 超范围 | 空输入、无字段匹配 | 引导至模型/维度/指标 | 引导面板 |

### 5.5 界面引导与引擎对照

| 界面引导 | 对应意图簇 | 方案摘要 |
|----------|------------|----------|
| 看模型/数据集 | metadata_model | 读目录，不查数 |
| 看维度/指标/度量/口径 | metadata_* / definition | 读语义层 |
| 看数值 | analytical_aggregate 等 | 完整 NL2SQL |
| 看趋势/排名/占比/对比 | trend / rank / ratio / compare | NL2SQL + 专用图表 |
| 看明细 | analytical_detail | 明细 SQL + 表格 |

### 5.6 架构能力映射

| 提问类型 | 数据层依赖 | 功能/运营依赖 |
|----------|------------|---------------|
| 元数据类 | 统一元数据、模型看板 | 术语管理、历史提问 |
| 分析类 | 数据指标、数据标签 | LLM、SQL 问答对、动态提示词 |
| 澄清/追问 | 多数据集消歧 | NLP 追问、显隐反馈 |
| 图表类 | 指标口径一致 | NL2Chart、推荐问题 |

### 5.7 推荐使用路径

1. **冷启动：** 问候/帮助 → 元数据探查（模型→数据集→维度/指标）→ 口径确认  
2. **日常分析：** 汇总 → 趋势/排名/占比/对比/KPI  
3. **深度分析：** 明细下钻 → 多表/复杂 SQL（行业台账）  
4. **异常兜底：** 澄清选数据集 → 超范围引导 → 反馈沉淀 SQL 问答对  

### 5.8 一句话总结

**先认知（元数据 6 类）→ 再分析（指标 7 类）→ 全程辅助（引导/澄清/超范围）**；认知类走元数据与口径，分析类走语义解析与 NL2SQL，歧义由澄清与运营闭环承接。

### 6.3 推荐问句示例（产品内置）

**元数据：** 都有哪些模型？有哪些数据集？都有哪些维度？合同额是什么意思？  

**分析：** 今年各月销售趋势如何；帮我查今年每个部门的合同额；各产品种类销售量占比；美式与拿铁销售量对比；列出咖啡销售全部明细。  

**建筑物料（复杂）：** 入库金额超过全公司平均 2 倍的物料；多表关联与子查询类场景问句（见引擎 `CONSTRUCTION_MATERIAL_RECOMMEND_QUESTIONS`）。
