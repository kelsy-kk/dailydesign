# 术语中心产品规划

## 一、定位与价值

术语中心是数据中台「语义一致性」的锚点：把业务口语（合同额、GMV、签约日期）沉淀为受治理的标准词汇，再通过「挂载」机制向下扎根模型、向上支撑指标，最终保证字段命名、指标口径、报表表达说的是同一种话。

一句话定义：

> 向下承接「术语库 → 数据域 → 模型」的归属体系，向上支撑「字段挂载 → 指标引用 → 词根同步」的引用链路，中间用「上线 / 下线」状态控制术语的可挂载性。

本规划依据现有业务建模原型（`index_v2.0.html`、`term-module.js`）的实现逻辑梳理，并对标 OpenMetadata Glossary 的产品能力，输出术语中心的数据操作闭环与上下游逻辑。

## 二、概念模型与对象关系

### 2.1 对象分层

- **术语库（Glossary）**：对标 OpenMetadata Glossary，承载名称、描述，并绑定唯一数据域。
- **术语（GlossaryTerm）**：对标 OpenMetadata GlossaryTerm，承载名称、同义词、描述、所属数据域、生效模型、状态、负责人与创建时间。

### 2.2 关系矩阵

| 关系 | 方向 | 说明 |
| --- | --- | --- |
| 术语库 → 术语 | 一对多 | 库绑定数据域，是术语默认域的来源 |
| 术语 → 数据域 | 多对多 | 术语至少属于一个域，可跨域 |
| 术语 → 模型 | 多对一（集合） | 生效模型必须是所属数据域下模型的子集，为空表示该域下全部模型生效 |
| 术语 → 字段 | 多对多 | 挂载记录以「模型名 + 字段英文名」为键，可互挂多对 |
| 术语 → 指标 | 一对多 | 指标侧持有术语 id 列表，形成引用关系 |
| 术语 → 词根 | 一对多 | 已上线术语可同步至词根库，供物理建模复用 |

### 2.3 关键规则

1. 术语的数据域必填，且是权限过滤的边界。
2. 术语的生效模型必须落在其数据域范围内；换域时自动裁剪越界模型。
3. 术语库绑定的数据域，决定新建、导入术语时的默认域（继承后可修改）。
4. 一个字段可挂载多个术语，一个术语也可挂载到多个字段；被用户忽略的推荐挂载单独记录，避免重复打扰。

## 三、数据模型

### 3.1 术语

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | 字符串 | 术语唯一标识，创建时生成 |
| name | 字符串 | 术语名称，必填 |
| synonyms | 字符串 | 同义词，逗号或顿号分隔 |
| description | 字符串 | 业务定义 |
| domains | 数组 | 所属数据域（多选） |
| domain | 字符串 | 数据域拼接展示字段 |
| modelNames / modelIds | 数组 | 生效模型及其标识；为空即对数据域下全部模型生效 |
| project | 字符串 | 所属工程，默认继承当前工程 |
| online | 布尔 | 上线状态，新建默认未上线 |
| creator / createdAt | 字符串 | 创建人与创建时间 |

### 3.2 字段挂载关系

挂载关系以「模型名 + 字段英文名」为键，值为术语 id 数组；同时维护一份忽略清单，记录用户主动忽略的推荐挂载，便于后续恢复。

### 3.3 术语库

术语库包含 id、名称、描述与绑定数据域。绑定数据域是术语默认域继承、库内术语列表过滤、关系图谱展示范围的统一依据。

## 四、增删改逻辑（核心操作全流程）

### 4.1 创建

1. **入口**：术语库内「新建」按钮，空库提供空状态引导。
2. **表单**：名称（必填）、数据域（必填多选，默认继承术语库绑定域并给出继承提示）、生效模型（先选域后选模型，域变化时自动裁剪越界模型）、同义词、描述。
3. **重名校验**：输入过程即联想，按所选数据域范围查重，提示形如「某数据域已存在同名术语：A、B，请调整名称或数据域，确定则直接覆盖」。重名不拦截，确认后覆盖保存——治理取向以收敛为先。
4. **保存结果**：新术语置顶展示，默认未上线，并提示「上线后可供挂载」。

### 4.2 编辑

- 回填全部字段，数据域与生效模型的联动约束与创建一致。
- 重名校验排除自身。
- 修改数据域或生效模型后，既有引用不丢失：系统按最新的生效范围重新过滤展示，恢复即重新生效。

### 4.3 删除

- 单条删除前必须确认，并强制提示引用量，例如「该术语已挂载 N 个指标、M 个字段，删除后指标 / 字段上的对应挂载引用将一并失效」。
- 批量删除先汇总引用统计，确认后一并删除。
- 删除为硬删除，引用随术语缺失自然失效。

### 4.4 上线与下线

- 支持单条操作与批量操作。
- **上线是挂载的前提**：未上线术语不进入字段推荐匹配，也不进入提供给指标侧的候选池。
- 下线不解除既有挂载，存量引用继续保留与展示，仅冻结新增挂载。

### 4.5 批量操作

| 操作 | 逻辑 |
| --- | --- |
| 批量移动数据域 | 选择目标域后整体替换术语数据域，自动裁剪越界生效模型，并在执行前做重名冲突预检与提示 |
| 批量上线 / 下线 | 直接切换状态，反馈处理条数 |
| 批量删除 | 汇总引用后确认删除 |

### 4.6 批量导入（四步向导）

1. **上传**：读取 CSV，自动识别 UTF-8、GBK、GB18030 编码；表头必须包含「术语名称、同义词、术语描述」，支持常见别名映射；可下载模板或使用示例文件；上传文件自动归档到文档中心。
2. **设置**：选择目标数据域（默认继承术语库绑定域并可修改）；选择导入模式——
   - 新增模式：域内重名行报错，不可覆盖；
   - 更新模式：域内重名行标记为更新；
   - 覆盖模式：先清空目标数据域下全部术语，再执行导入。
3. **预览**：逐行校验（名称是否为空、文件内是否重名、新增模式下域内是否已存在），汇总「共 N 行：可新增 X，将更新 Y，失败 Z」，失败行标红并给出原因。
4. **确认导入**：更新与覆盖模式下，数据域按并集合并处理。

### 4.7 导出与模板

- 导出按当前筛选结果输出 CSV，表头与导入模板一致，空结果给出提示。
- 模板下载包含标准表头与一行示例，并写入 BOM 以兼容 Excel 中文显示。

## 五、向下逻辑：术语的定义基础

术语的合法性由三层基础设施背书：

1. **术语库层**：库绑定唯一数据域，决定新建与导入术语的默认域、左侧库列表的术语计数口径，以及空状态的显隐判断。
2. **数据域层**：数据域是术语的身份与权限边界。术语必须至少属于一个域；列表读取时按数据域访问权限过滤，用户看不到无权域内的术语。
3. **模型层**：生效模型限定术语的适用范围。字段推荐匹配时——术语锁定模型则仅对锁定模型生效；未锁定则对其所属域下的全部模型生效；模型不在术语所属域内则永不生效。

向下变更的向上传播：

- 修改数据域，越界生效模型被裁剪，原先依赖「域默认生效」的字段挂载在图谱与详情中不再展示。
- 修改同义词或描述，字段推荐匹配的命中面随之变化。
- 切换上线状态，控制新增挂载的开关。

## 六、向上逻辑：术语的引用消费

### 6.1 字段挂载（自动推荐 + 手动确认）

- **精确命中**：字段英文名或中文名等于术语名称或任一同义词（忽略大小写与空白）。
- **推荐命中**：字段描述与术语描述相似度达到阈值（基于中英文兼容的字符二元组重叠算法）。
- **匹配范围**：已上线，且对该字段所在模型生效的术语。
- **确认与忽略**：用户可采纳推荐完成挂载，也可忽略；忽略后不再重复打扰，且支持恢复。

字段挂上术语，即该字段获得标准业务定义，是「字段 → 指标」口径可信的第一环。

### 6.2 指标引用

指标可引用多个术语；候选池来自已上线且同工程的术语。引用关系在指标详情中展示并支持跳转。

### 6.3 术语详情（引用反查）

详情抽屉包含基本信息与两份引用清单：

- **关联指标清单**：所有引用该术语的指标，点击直达。
- **关联字段清单**：有效挂载记录与当前字段表中匹配命中的字段，点击直达。

引用计数同时服务于删除确认与重名提示。

### 6.4 关系图谱

以四列结构全景展示：**模型 → 字段 → 术语 → 指标**。三类连线分别为「模型 → 术语」（生效关系）、「字段 → 术语」（挂载关系）、「术语 → 指标」（引用关系）。图谱范围限定为当前术语库绑定域下的术语及其全部引用，并以统计条呈现四类节点数量。交互支持悬停高亮一度关联、点击锁定、缩放与平移，空图谱提供引导态。

### 6.5 同步到词根

术语作为词根库的上游输入：将已上线术语推送至词根管理，供物理建模侧复用命名规范。规划上应具备范围选择、重名冲突检测、增量写入与同步记录留痕。

## 七、状态机与生命周期

| 状态 | 可执行操作 | 引用能力 |
| --- | --- | --- |
| 未上线（新建与导入默认） | 编辑、删除、上线 | 不参与字段推荐与指标候选 |
| 已上线 | 编辑、删除、下线 | 参与字段推荐与指标候选，受存量引用保护 |

任意状态均可删除，删除前强制提示引用量。下线不破坏存量引用，只冻结新增挂载。

## 八、权限模型

现状以数据域为权限边界，工程为二级范围。规划补齐角色维度：

| 角色 | 能力 |
| --- | --- |
| 术语库负责人 | 库级设置、成员管理、术语审批 |
| 术语评审人 | 上线审批、描述变更审批 |
| 数据域编辑者 | 域内术语的增删改 |
| 只读用户 | 查询与引用，无编辑权限 |

## 九、与 OpenMetadata Glossary 的对照

| 能力 | OpenMetadata | 当前实现 | 规划取舍 |
| --- | --- | --- | --- |
| 层级结构 | 术语支持多级父子树 | 术语库到术语的扁平结构 | 支持术语父子层级，继承数据域与生效模型 |
| 关联术语 | 独立维护关联与反义关系 | 仅同义词字段 | 增加关联术语的独立引用 |

| 引用统计 | 按实体打标计数 | 指标与字段挂载计数 | 已实现，口径一致 |
| 活动信息流 | 任务与评论协作 | 页签已预留未启用 | 记录增删改、上线、挂载事件并支持评论 |

| 删除 | 递归软删除子术语 | 硬删除并提示引用失效 | 保持硬删除，长期引入回收站 |

## 十、演进路线

### 10.1 第一阶段（现有原型已覆盖）

术语库管理、术语增删改查、上线与下线、批量操作、四步导入与导出模板、重名治理、字段推荐挂载、指标引用、引用反查、关系图谱、数据域级权限过滤、词根同步入口。

### 10.2 第二阶段

1. 术语父子层级与关联术语，对齐 OpenMetadata 的术语模型。
2. 活动信息流启用：全操作留痕与评论协作。
3. 负责人与评审人角色，未审批不可上线。
4. 导入扩展列（层级、关联术语）；引用统计面板化。
5. 词根同步闭环：冲突检测与同步记录。

### 10.3 第三阶段

1. 术语版本化与变更对比。
2. 智能问数联动：术语与同义词作为自然语言查询词表，直接服务问数场景。
3. 软删除回收站与递归删除治理。
4. 术语健康度指标：按数据域统计字段挂载覆盖率，驱动治理运营。

## 十一、术语中心全景逻辑

向下、向上两条链路与中间状态控制共同构成术语中心的数据闭环：

1. **输入侧（向下扎根）**：术语库绑定数据域 → 数据域决定归属与权限 → 生效模型限定适用范围。术语由此获得合法身份与生效边界。
2. **状态控制（中间）**：未上线与已上线之间的切换，是挂载能力的总开关；重名治理与引用统计构成数据质量护栏。
3. **输出侧（向上消费）**：字段挂载沉淀业务定义 → 指标引用统一口径 → 词根同步服务物理命名。三者共同反哺建模与问数场景。
4. **全景视图**：关系图谱以「模型 → 字段 → 术语 → 指标」四列串起全部引用链路，配合术语详情的双向跳转，形成可追溯、可验证的语义资产网络。
